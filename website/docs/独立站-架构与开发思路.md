# 个人官网 — 独立站架构与开发思路

> 版本：v1.0  
> 日期：2026-06-04  
> 说明：**不依赖** `server.jiankalka.cn` 与微信小程序；与仓库内 `miniapp/`、`server/` 可完全并行、零耦合。

---

## 1. 两种建设路线（二选一）

| 路线 | 适用 | 账号与数据 |
|------|------|------------|
| **A. 独立站（本文）** | 个人品牌、产品营销、自有小工具 | 自建用户库；与考研/小程序无关 |
| **B. 对接现有 API** | 希望官网与小程序同一账号 | 见 [个人官网-设计方案.md](./个人官网-设计方案.md)、[API与登录对接.md](./API与登录对接.md) |

**推荐**：若官网目标是「充电桩产品展示 + 自己的工具」，选 **路线 A**，简单、可维护、发版互不影响。

---

## 2. 系统要做什么（功能边界）

```
┌─────────────────────────────────────────────────────────────┐
│  对外（访客）                                                  │
│  · 首页 / 产品 / 方案 / 案例 / 关于 / 联系                       │
│  · 可选：留言、资料下载、SEO                                    │
├─────────────────────────────────────────────────────────────┤
│  对内（可选登录）                                              │
│  · 会员：收藏、下载记录、工具使用次数                             │
│  · 管理：产品/文章 CRUD、留言处理、站点配置                       │
├─────────────────────────────────────────────────────────────┤
│  小工具（可纯前端或需后端）                                      │
│  · 计算器、单位换算、二维码生成/解析、文档/参数计算器               │
│  · 充电桩：参数说明、选型助手（表单+公式，无需 BLE）                 │
└─────────────────────────────────────────────────────────────┘
```

与小程序 **无强制关系**：蓝牙调试、运维平台等留在 App/小程序即可；官网只做营销与 **Web 能完成的工具**。

## 3. 技术语言选型（建议组合）

### 3.1 推荐栈（个人站、一人维护）

| 层级 | 语言 / 运行时 | 框架 / 库 | 用途 |
|------|----------------|-----------|------|
| **前端** | TypeScript + HTML/CSS | **Vue 3** + Vite，或 **Nuxt 3**（要 SEO 时） | 页面、工具 UI、管理台 |
| **后端** | **Node.js (TypeScript)** 或 **Python 3** | Express/Fastify 或 FastAPI | REST API、登录、管理、邮件 |
| **数据库** | SQL | **SQLite**（起步）→ **PostgreSQL/MySQL**（流量上来） | 用户、内容、留言 |
| **部署** | — | Nginx + 宝塔 / Docker | 静态 + 反代 API |

**样式**：Tailwind CSS 或 SCSS；**内容**可用 Markdown + JSON（产品参数），不必上重型 CMS。

### 3.2 其他可选（按熟悉度）

| 场景 | 前端 | 后端 | 说明 |
|------|------|------|------|
| 全 JS 一人栈 | Vue/Nuxt | Node (Express/Nest) | 与现有 `server/` 技术相近，但**新仓库/新进程** |
| 偏 SEO、内容站 | **Astro** + Vue 岛屿 | 无或 Serverless | 营销页极快，工具页用 Vue 岛 |
| 偏 Python | Vue 或纯 HTML | **FastAPI** | 适合以后接数据分析、脚本 |
| 极简、几乎无后端 | 仅 **Astro/Next 静态** | 无 | 工具全浏览器端；联系用表单第三方（Formspree） |
| 国内云一体 | uni-app H5 | 云开发 | 与小程序同栈，但仍是**独立项目** |

**语言结论**：前端 **TypeScript + Vue 3**；后端 **Node.js (TS)** 或 **Python** 二选一即可，不必两种都上。

## 4. 系统架构划分（逻辑分层）

```
                    [ 用户浏览器 ]
                           │
           ┌───────────────┴───────────────┐
           ▼                               ▼
   ┌───────────────┐               ┌───────────────┐
   │  营销与工具前端  │               │  管理后台前端   │
   │  (www 主站)    │               │  (/admin)     │
   │  Vue / Nuxt    │               │  Vue 同栈      │
   └───────┬───────┘               └───────┬───────┘
           │         HTTPS /api            │
           └───────────────┬───────────────┘
                           ▼
                 ┌─────────────────┐
                 │   应用服务层       │  ← 业务：认证、产品、工具、留言
                 │   (API Server)    │
                 └────────┬────────┘
                          │
           ┌──────────────┼──────────────┐
           ▼              ▼              ▼
    ┌──────────┐   ┌──────────┐   ┌──────────┐
    │ 关系库    │   │ 对象存储   │   │ 邮件/SMS  │
    │ SQLite/  │   │ 本地/OSS  │   │ 可选      │
    │ MySQL    │   │ 图片附件   │   │          │
    └──────────┘   └──────────┘   └──────────┘
```

| 层 | 职责 | 是否必须 |
|----|------|----------|
| **展示层** | 营销页、工具页、响应式布局 | 必须 |
| **API 层** | 登录、内容 CRUD、工具需服务端的能力（如发邮件、存留言） | 有登录/后台则必须 |
| **数据层** | 用户、文章、产品、配置 | 同上 |
| **基础设施** | Nginx、SSL、备份、日志 | 上线必须 |

**纯前端工具**（计算器、简单换算）可放在展示层，**不经过 API**。

## 5. 前后端分离 vs 合在一个后端应用

### 5.1 三种部署形态

| 形态 | 结构 | 优点 | 缺点 |
|------|------|------|------|
| **① 前后端分离（推荐）** | 前端静态 `dist` + 独立 API 进程 | 职责清晰；前端可 CDN；API 可单独扩容 | 两个构建/两个目录 |
| **② 单体 BFF** | 一个 Node 服务：Express 提供 `/api` + `express.static` 托管前端 `dist` | 一个域名、一个 PM2、部署简单 | 前后端发布绑在一起 |
| **③ 全静态** | 仅 Nginx 托管 HTML/JS | 成本最低、最快 | 无自建登录与后台；动态能力弱 |

### 5.2 怎么选（直接建议）

| 你的情况 | 建议 |
|----------|------|
| 只有产品页 + 纯前端小工具 + 联系表单走第三方 | **③ 全静态**（Astro/Nuxt generate） |
| 要自己的登录、留言入库、简单管理后台 | **② 单体** 或 **① 分离** 均可 |
| 一人维护、宝塔单机、希望省事 | **② 单体**：`website-api` 一个进程同时挂 `/api` 和静态站 |
| 以后可能 App、多端复用 API | **① 分离**：`www` 静态 + `api.jiankalka.cn`（或 `www.../api` 反代） |

**结论**：

- **开发上**：无论 ① 还是 ②，代码仍建议 **两个子目录**（`web/` + `api/`），便于阅读与测试。
- **部署上**：个人站用 **② 单体** 完全够用；流量或团队变大再拆成 ①。

```
推荐仓库结构（独立站，与 miniapp/server 无关）：

website/
├── web/                 # Vue3 + Vite 或 Nuxt
│   ├── src/pages/       # 营销 + /tools
│   └── src/admin/       # 可选：管理台（或单独 admin-web）
├── api/                 # Node + Express/Fastify 或 Python FastAPI
│   ├── src/routes/
│   ├── src/services/
│   └── prisma/ 或 migrations/
├── content/             # 产品 JSON、Markdown
└── docs/
```

单体部署时：`api` 构建后把 `web/dist` 复制到 `api/public`，由同一进程提供。

## 6. 开发思路（分阶段）

### 阶段 0：定范围（1 天）

- 列出必须页面与工具清单。
- 决定是否要登录；无登录则全程静态 + 表单外链。

### 阶段 1：营销壳（1–2 周）

- 技术：`web/` 用 **Vite + Vue 3 + TypeScript**。
- 内容：产品数据放 `content/products/*.json`，页面读 JSON 渲染。
- 部署：Nginx 只放 `dist`，域名 `www.jiankalka.cn`。

### 阶段 2：纯前端工具（约 1 周）

- 计算器、二维码（`qrcode` npm 库）、选型助手等在浏览器完成。
- **无需后端**。

### 阶段 3：轻量后端（按需，1–2 周）

- `api/`：**Node + Express + SQLite**（或 MySQL）。
- 功能：管理员登录、产品/案例 CRUD、留言表、上传图片。
- 认证：JWT 或 Session；管理员一种角色即可。

### 阶段 4：管理台（与阶段 3 并行）

- 简单 Vue 后台：列表 + 表单，调用自家 `/api/admin/*`。
- 可与主站同仓 `web/src/admin`，路由前缀 `/admin`。

### 阶段 5：增强（可选）

- 邮件通知、访问统计、评论审核、多语言、CDN。

## 7. 独立站 API 设计概要（自建，非 server.jiankalka.cn）

| 模块 | 示例路径 | 说明 |
|------|----------|------|
| 健康检查 | `GET /api/health` | 运维 |
| 认证 | `POST /api/auth/login`、`POST /api/auth/register` | 邮箱/手机+密码 |
| 公开内容 | `GET /api/products`、`GET /api/posts/:slug` | 也可静态 JSON 免 API |
| 留言 | `POST /api/contact` | 入库 + 邮件 |
| 管理 | `GET/POST/PUT/DELETE /api/admin/*` | 需管理员 JWT |
| 工具 | 多数无 API；若生成 PDF/大图可 `POST /api/tools/...` | 按需 |

数据库表示例：`users`、`products`、`posts`、`contacts`、`site_config`。

## 8. 与现有仓库的关系

```
jiankalka-kaoyan/
├── miniapp/      # 微信小程序（考研 + 工具箱）— 不耦合
├── server/       # 考研 API + admin — 不耦合
└── website/      # 个人官网独立工程
      ├── web/
      ├── api/      # 可选；纯静态阶段可没有
      └── docs/
```

- **域名**：仍可用 `www.jiankalka.cn` 指向 `website/web` 构建产物；**不必**解析到 `server` 子域。
- **未来若需打通**：再做「账号绑定」集成层（OAuth、同一邮箱映射），属于二期，非架构前提。

---

## 9. 安全与运维（独立站）

- HTTPS、`.env` 不入库、管理员强密码、生产关闭自助注册（若仅自用后台）。
- SQLite 定期备份；改 MySQL 后走宝塔定时备份。
- 上传文件类型与大小限制；管理接口限流。
